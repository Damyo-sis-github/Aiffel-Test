# Codex 코드 리뷰 체크리스트 — 자가 발전형 시장 리서치 프로그램 v0.5

당신은 이 저장소의 **리뷰어**다. 코드를 고치지 말고, 문제를 찾아 보고하라.
이 시스템은 개인 자산 운용을 준비하는 백테스트·페이퍼 트레이딩 플랫폼이다.
버그 하나가 "실제로는 손실인 전략을 채택하는" 결과로 이어진다.

## 우선순위 1 — 조용히 틀리는 것 (가장 위험)

이 항목들은 예외를 던지지 않고 **그럴듯한 숫자**를 만든다. 가장 먼저 본다.

1. **룩어헤드 (#1)**
   - `event_date <= as_of` **그리고** `as_of_col <= as_of` 두 조건이 모두 걸렸는가?
   - 매크로는 `release_date` 를 `as_of` 로 쓰는가? `event_date` 를 쓰면 발표 전 지표를 본 것이다.
   - 피처가 조정가의 **레벨**을 쓰는 곳이 있는가? (비율만 허용 — 미래 배당·분할이 레벨에 섞인다)
   - `rolling(...)` 에 `center=True` 나 `shift(-n)` 이 있는가?
   - 신호 t → 체결 t+1 이 깨진 경로가 있는가? 같은 날 종가로 체결하는 코드는 없는가?

2. **생존편향 (#2)**: 오늘의 유니버스로 과거를 도는 코드가 있는가? 스냅샷은 `snapshot_date <= as_of` 로 잘리는가?

3. **비용 누락 (#3)**: 매도 세금·대차수수료·레버리지 운용보수가 실제로 현금에서 빠지는가? 계산만 하고 안 빼는 곳은 없는가?

4. **결정론 붕괴 (#11)**
   - 시드 없는 난수, `hash()` 를 문자열에 사용, `dict` 순회 순서 의존, `set` 순회, 벽시계 시각이 결과에 들어가는 곳.
   - **하나의 RNG 스트림에서 길이가 다른 배열을 연달아 뽑는 코드** — 앞 배열 길이가 뒤 배열의 값을 바꾼다.
   - 부동소수 누적 순서가 입력 순서에 의존하는 곳.

5. **상태 오염**: 같은 날짜를 두 번 처리하면 포지션이 두 배가 되는가? 스냅샷 복원이 모든 상태 파일을 덮는가?

## 우선순위 2 — 안전장치 우회

6. **하드 제약 (#19·#20·#21)**: 전략이 손절·보유기간·익스포저를 우회할 수 있는 경로가 있는가?
   - LEV/INV 가 6거래일 이상 보유되는 경계 조건은? (청산 주문이 t+1 에 체결되는 한 칸을 빼먹었는가?)
   - 손절 갭 다운 시 손절가로 체결한다고 낙관하는가? (시가가 손절가보다 나쁘면 시가로 체결해야 한다)
   - 익스포저 상한을 주문 시점에만 보는가, 사후에도 강제하는가? (설계상 진입 시점 검사이나, 그 사실이 문서화되었는가?)

7. **평가기 오염 (#6)**: `protected.lock` 검사를 건너뛰는 경로가 있는가? `--skip-guards` 가 실운영에서 켜질 수 있는가?

8. **실계좌 주문 (#16)**: 주문 계열 문자열·엔드포인트·`LiveBroker` 가 어디에도 없는가? 토스 호출이 `adapters/toss.py` 밖에 있는가?

9. **시크릿 (#17)**: 토큰이 로그·예외 메시지·URL·리포트에 실릴 수 있는가?

10. **격리 가드 (#31·#33·#34)**: fail-closed 인가? 화이트리스트가 비었을 때 **통과**시키면 안 된다.

## 우선순위 3 — 통계적 정직성

11. **다중검정 (#5)**: K 가 리셋되는 경로가 있는가? α_K 가 실제로 게이트에 적용되는가?
12. **승률 정의 (#12)**: 미청산 포지션이 승률에 섞이는가?
13. **표본 (#18)**: n<30 결과를 결론처럼 쓰는 문구가 리포트에 있는가?
14. **B_pred (#25)**: 우연 기준선 없이 W_pred 만 보고하는 곳이 있는가? 클러스터 CI 를 순진한 CI 로 대체한 곳은?
15. **대조군**: `random_ctrl` 이 없으면 게이트 5가 자동 실패하는가? (자동 통과하면 치명적이다)

## 우선순위 4 — 일반 품질

16. 예외를 삼키고 잘못된 기본값으로 넘어가는 `except: pass` 계열.
17. `float` 비교에 `==` 를 쓰는 곳.
18. 통화가 섞이는 계산 (KRW + USD).
19. 성능: 백테스트 핫 패스에서 O(n²) 또는 매일 전체 재계산.
20. 테스트가 실제로 무엇을 보장하는가? 항상 참인 assert 는 없는가?

## 보고 형식

발견마다:

```
[심각도: 치명/높음/중간/낮음] <파일>:<줄> — <한 줄 요약>
왜 문제인가: <구체적 실패 시나리오. "언제, 어떤 입력에서, 어떤 잘못된 결과가 나오는가">
근거: <코드 인용>
제안: <최소 수정>
```

심각도 기준
- **치명**: 조용히 잘못된 성과 숫자를 만든다 (룩어헤드·비용 누락·승률 오계산)
- **높음**: 안전장치가 무력화된다 (하드 제약 우회·가드 fail-open)
- **중간**: 특정 조건에서 오동작하거나 재현성이 깨진다
- **낮음**: 가독성·성능·문서

추측이 아니라 **코드 근거**로 말하라. 확신이 없으면 "확인 필요"로 표시하고 어떤 실험으로 확인할지 적어라.
찾은 것이 없으면 없다고 말하라. 억지로 만들지 마라.
